# StudyRoom implementation contract

Monorepo npm workspaces: apps/web (React18/Vite/TypeScript), apps/api (NestJS/Prisma/PostgreSQL), apps/ai-gateway (Node TypeScript local authenticated Ollama gateway). Spanish UI. Base API /api. JSON errors {message,code?}; Firebase ID token Bearer; user id is Firebase uid. Browser never receives server secrets. ISO UTC dates; user timezone display. Local development uses real Firebase Auth emulator and PostgreSQL; no mock authentication in production.

All requirements are in jira-requirements.json (657), story-requirements.md (50), task-requirements.md (150), epic-requirements.md (7). Activities must also be read from JSON and traced honestly. Do not mark untested requirements verified.

## Realtime

Events chat:message (Message), room:members (members), room:updated (Room), room:closed ({roomId}), timer:updated (timer), annotation:updated ({action,screenId,userId,x,y,points,color}), ai:updated (job), room:reaction ({userId,emoji}), room:hand ({userId,raised}). Client emits room:reaction {roomId,emoji}, room:hand {roomId,raised}. REST for persistent mutations; socket is notification/resync. No secret or private notes broadcast. Reauthorize every event. On reconnect rejoin+snapshot. Multiple tabs counted once. Media continues separately in LiveKit.

### Desktop drawing requested on 2026-10-02
The user's clarification extends SUT-41: drawing must remain available over the Windows desktop and other applications, with a small expandable square at the upper right. `apps/desktop` provides a local transparent always-on-top companion with pencil, object eraser, clear, rectangle, ellipse, line, arrow, text, color, stroke width and text size. Interaction mode passes input to the underlying desktop; Escape returns to interaction without clearing marks. The person sharing sees the marks immediately on their own desktop.

The companion does not capture the screen or connect to external services. A loopback-only bridge on `127.0.0.1:8790` accepts an exact-origin, JSON sharing lease `{sessionId,active}` from StudyRoom; it receives no account identity, screen content or credentials. Only a published local screen track starts the lease. Camera/microphone actions never await or activate it. Heartbeats renew the lease without resetting drawing tools; the last stop or expiration hides the panel and drawings. Accidentally closing the panel during an active lease restores the small button. Initial installation starts the companion in the background; after restarting Windows it must be opened once, and browser local-connection prompts remain under user control.

When the user chooses the full monitor in the browser's screen-sharing picker, LiveKit transmits those visible desktop marks as part of that screen's video. A tab or single-window capture does not include independent desktop overlays. Screen capture continues to require the user's browser selection. `studyroom-tools://open` is a fixed local launch action without credentials or arbitrary command arguments; registration is per user and reversible. The web's normalized room annotations remain separately authorized and synchronized.

The original Jira snapshot is retained. See [desktop tools](desktop-tools.md) for installation and limits, and [manual acceptance](acceptance-manual.md) for the separate full-monitor, cross-application and remote-viewer checks.
